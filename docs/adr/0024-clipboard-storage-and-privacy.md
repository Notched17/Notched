# ADR-0024: Clipboard history: storage, privacy and the hotkey

- Status: accepted for M4b Step 2 (#45); **written on Linux, not yet compiled or run**
- Date: 2026-10-31
- Spec: `docs/superpowers/specs/2026-10-31-m4b-productivity-design.md` §4.2, §8

## Decisions

- **Polling is one integer compare.** `NSPasteboard.changeCount` is checked every 0.5 s through `RefreshScheduler` (1 s on battery, 2 s in Low Power Mode). The pasteboard is read only when the count moved. The first count seen after start is silent.
- **Skip before reading.** `ClipboardPolicy` looks at the pasteboard's *types* and the frontmost app first. Items carrying `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType` or a few legacy password-manager types are never read. The reducer checks again. A default exclusion list covers common password managers by bundle ID (editable). The "source app" is the frontmost app at the moment the change is seen, which can be wrong for a background app.
- **Storage: a JSON index plus one PNG per image**, in `~/Library/Application Support/Notched/Clipboard/` (folder 0700, files 0600), written atomically by a serial background queue 2 s after a change and on quit. No SQLite or SwiftData: a few hundred items need no query engine, it adds no dependency or background work, and the logic tests with plain Foundation. This departs from the ROADMAP's suggestion.
- **Not encrypted.** The files are private to the user but plain. The settings pane says so and offers exclusions, Clear History and Clear on quit. Contents are never logged.
- **Limits.** Text over 100 KB and images over 5 MB (after shrinking to 2048 px) are not kept; cutting text would make copy-back wrong. Default 200 items; pins don't count and survive Clear. The prompt suggested 1 MB text; 100 KB keeps the worst-case index near 20 MB in memory.
- **No auto-paste.** Click copies back and collapses the island; nothing posts key events.
- **Own copy-backs are not recorded again**, by remembering the change count the write produced.
- **Hotkey:** sindresorhus/KeyboardShortcuts (MIT, Carbon `RegisterEventHotKey`: public, no permission, no event tap). Default ⌘⇧V, which many apps use for Paste and Match Style, so it is changeable and can be turned off; the tab and a status-menu item always work.
- **Opening on a tab** needed a new seam, `IslandCommands` (`showTab`, `collapse`) in `ModuleServices`, connected by `AppEnvironment`.

## Open until checked on the Mac

- **macOS's pasteboard-privacy prompt (26+).** Reading `changeCount` should never prompt; reading contents may. Not yet checked on 27.2: whether a background agent gets one prompt or one per read, whether a denial can be detected (the tab would then say so), and what the first copy looks like to the user. Nothing in the code depends on the answer yet.
- **Keyboard focus for the search field.** The island takes key status only after a click (ADR-0020). `showTab(focus: true)` asks for it one run-loop turn after expanding; unverified that typing works straight away.
