## Part B: iPhone-style island behaviour
Implement `docs/ISLAND-BEHAVIOR.md` §1–§6 and fix every item in §8. Suggested order, with build, test, screenshot and commit after each step:

1. **Model and coordinator (TDD first).**
   - Write the `LiveActivity` model and the new coordinator.
   - Write the scenario tests before the code. Include at least:
     - one activity → compact
     - two activities → primary + 1 minimal, with the primary chosen by class, then relevance, then start order
     - four activities → 3 visible, 1 listed only
     - an alert update → alert-expansion queue entry, then back to the previous state
     - two alerts at once → shown one after the other
     - a transient banner during multi → pre-empts, then restores
     - swap is sticky until an activity ends
     - hide keeps the activity running and lists it
     - a non-hideable activity ignores hide
     - stale → stale look
     - ended → off the island immediately, stays in Recent until its dismiss time
   - Inject the clock as before. No polling.
2. **Presentation template.**
   - Add `ActivityPresentation` with the regions from spec §4, plus the custom expanded-region `Layout`.
   - Migrate `HelloModule`, and delete the old `ActivityContent` API.
   - The island now owns content animation: blur-replace swaps, `numericText`, symbol effects, ≤ 2 s. Ignore the modules' own animations.
3. **Compact rendering.**
   - One activity owns both compact slots.
   - Compact views hug the notch with balanced widths.
   - An empty trailing slot hides itself.
4. **Minimal bubbles.**
   - Detached black circles or ovals: trailing first, then leading.
   - A 6 pt gap.
   - A bud-off and merge spring.
   - Optional keyline tint.
   - Respect the width budget and click-through.
   - Also build the "Side-by-side (iPhone 18 Pro style)" layout option.
5. **Alert expansion and transient banners.**
   - Alerts expand the island to that activity's expanded view for the configured time, then return. If the pointer is over the island, don't interrupt the user; queue the alert instead.
   - Banners are the short, wide-compact path for system events.
   - Keep the bounce for banners.
6. **Interaction:**
   - click → `openAction`
   - clicking a minimal bubble → it becomes primary
   - hovering an activity → that activity expands
   - two-finger horizontal swipe on compact → cycle the primary
   - swipe up or right-click → Hide
   - in the expanded view: page between all live activities and Home, with a subtle page indicator, plus an activity list with Hidden and Recent sections
   - Esc collapses
   - Add a "Click to expand" setting for people who prefer it.
7. **Settings additions:**
   - Multiple activities: Bubbles / Side-by-side
   - Alert expansion on/off and duration
   - Banner duration
   - Recent retention
   - Click behaviour
   - Keyline on/off
8. **Scenario Lab (DEBUG only).**
   - A status-menu submenu that drives realistic demo activities through the real coordinator, using fake modules:
     - "Music": artwork + bars, class media
     - "Timer": a counting-down glyph + time, class live, minimal shows the countdown
     - "Call": a green handset + duration, class system, not hideable
     - "Claude Code working…": class live
     - "Download 42%": a progress ring in minimal
     - a "Charging 80%" banner
     - an "Alert: timer done" update
   - Include buttons to end, stale, hide, swap each one, and a "Run full demo" that plays a scripted sequence.
   - The demos must look production-quality, because they define the visual language M2–M4 will follow.
