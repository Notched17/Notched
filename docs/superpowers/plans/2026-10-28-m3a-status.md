# M3a Status Modules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M3a: module lifecycle foundations, a shared banner pipeline, and six public-API status modules (#25 Caps Lock, #26 Battery, #27 Bluetooth, #29 Network, #37 Timers, #38 Keep-awake).

**Architecture:**
- **Part A (cloud session, Linux).** All the pure logic, Foundation-only and tested: lifecycle plan, launch guard, defaults, `BannerSource`, `BannerQueue`, and one reducer per module. Also the `@MainActor` glue that wires them in: `ModuleHost`, coordinator banner queue, ranking.
- **Part B (local session on the Mac).** The system shells and SwiftUI per module, then screenshots, robustness and performance.

**Tech Stack:** Swift 6, SwiftUI, AppKit, IOKit (power sources, PM assertions, HID registry notifications), CoreAudio, Network (`NWPathMonitor`), CoreWLAN, Core Animation, Swift Testing, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-10-28-m3a-status-design.md`

## Global Constraints

- Every source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later`.
- Swift 6 strict concurrency. UI and models are `@MainActor`. Reducers are `Sendable` value types with no system or SwiftUI imports (Foundation only).
- **A disabled module costs zero.** After `stop()`: no timer, listener, notification, run-loop source or assertion.
- **No polling:** IOKit notifications, CoreAudio listeners, `NWPathMonitor`, `NSEvent` monitors, `OneShotTimer` deadlines.
- Logging: `Log.module("<id>")`, never `print`.
- **Budget, all M3a modules on:**
  - idle < 0.5 % CPU
  - Now Playing compact < 1.5 %
  - a timer compact < 1 %
  - memory < 150 MB
  - measured with `scripts/cpu.sh`
- **Ranking:** `passive < live < media < system` (ADR-0011).
- **Banner policies (spec §4):**
  - network: 2 s settle, 3 per 60 s
  - charger: 10 s cooldown
  - low battery: `.high`
  - Bluetooth: 1 s connect settle, 2 s disconnect settle
  - Caps Lock: no limit, same id
- Builds and tests go through `build-runner` (`scripts/test.sh`). Part A's pure files also pass `swift test` on Linux (Swift 6.2.4) through a scratch harness, which isn't committed.

## Review Focus

1. **Wi-Fi flapping, e.g. a weak signal toggling every second for a minute:** expect at most 3 banners a minute, the last one announcing the real final state. Test: `NetworkReducerTests.flappingIsRateLimitedToFinalState`.
2. **Battery hovering at 20/21 % (the reading jitters):** expect exactly one low banner until the level is back above 23 %. Test: `BatteryReducerTests.jitterAtThresholdFiresOnce`.
3. **The Mac sleeps through a timer's end:** expect one alert on wake, with sound only if it ended under a minute ago, then Recent. Test: `TimersReducerTests.wakeLongAfterEndGoesToRecent`.
4. **AirPods reconnecting (a brief drop, or the CoreAudio device id changing):** expect no disconnect/connect pair. Test: `BluetoothReducerTests.reconnectBlipIsSilent`.
5. **Xcode's Stop button (SIGKILL) three times during development:** expect no safe mode while a debugger is attached. Test: `LaunchGuardTests.debuggerNeverEntersSafeMode`.

}
