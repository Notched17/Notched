# M3b Part B: HUD Replacement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to work through this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Before each task, state its model and effort in one line (CLAUDE.md policy); if the session is set differently, stop and ask. Builds, tests and `cpu.sh` go to `build-runner`; searches go to `Explore`.

**Goal:** replace the macOS volume HUD (#20), and the brightness HUD (#21) if this Mac's keys allow it, with island banners in four styles (#23). Use an event tap that can never leave the keys dead.

**Architecture:** an active session tap on `NX_SYSDEFINED` only, on its own thread (`MediaKeyTap`). It hands parsed keys to `HUDKeyEngine`, which runs the pure `HUDKeyReducer` twice per key: decide, apply the change synchronously through a `LevelControl`, then swallow or pass. HUD readings hop to the main-actor `HUDModule`, which shows them as top-priority `TransientBanner`s and owns the permission, the latch and the off switches.

**Tech stack:** Swift 6 (strict concurrency), CGEventTap, CoreAudio HAL, private DisplayServices via `dlopen` (B2), SwiftUI, Synchronization (`Mutex`), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-29-m3b-hud-tap-safety-design.md` (approved 29 Oct). Read it first; §-numbers below refer to it. Also the HUD rows in `docs/ROADMAP.md` and `docs/superpowers/specs/2026-10-28-m3b-system-design.md` ("Part B").

**Branch:** `m3b-system` (Part A plus c1228a1). Don't push or merge without asking.

**Interfaces (produces):**
```swift
enum HUDKind: Sendable, Hashable { case volume, brightness }
/// What one key asks for.
enum HUDStep: Equatable, Sendable { case level(HUDKind, delta: Double), toggleMute }
/// The logical target of a change whose read-back hadn't caught up (§3.3).
struct PendingTarget: Equatable, Sendable { let kind: HUDKind; let targetID: UInt32; let level: Double }
struct HUDReading: Equatable, Sendable { let kind: HUDKind; let targetID: UInt32; let level: Double; let isMuted: Bool; let atLimit: Bool }
enum ApplyOutcome: Equatable, Sendable {
    case changed(HUDReading)
    case atLimit(HUDReading)
    case unconfirmed(HUDReading, PendingTarget)
    case notSettable(HUDKind)
    case failed(HUDKind)
    /// The target is in pass-through (two unconfirmed presses).
    case skipped(HUDKind)
}
/// Called on the tap thread: must be Sendable and never touch the main actor.
protocol LevelControl: Sendable {
    func currentTarget() -> UInt32?          // default output device / built-in display
    func isSettable(_ id: UInt32) -> Bool
    func level(_ id: UInt32) -> Double?
    func setLevel(_ value: Double, on id: UInt32) -> Bool
}
protocol MuteControl: Sendable {
    func isMuted(_ id: UInt32) -> Bool?
    func setMuted(_ muted: Bool, on id: UInt32) -> Bool
}
enum LevelApplier {
    static func target(current: Double, pending: Double?, delta: Double) -> Double
    static func apply(_ step: HUDStep, pending: PendingTarget?, skipping: Set<UInt32>,
                      levels: some LevelControl, mute: (some MuteControl)?) -> ApplyOutcome
    static func reapply(_ pending: PendingTarget, levels: some LevelControl) -> Bool   // true once read-back reached it
}
```
Rules (§3): `target` starts from `pending ?? current`, rounds to the grid `1/|delta|` and clamps to 0…1. A read-back counts as reached if it's within 0.002 of the target, **or** moved at least 0.001 from the starting value towards it *(rounding hardware)*. If it stayed within 0.001 of the start, the outcome is `.unconfirmed`. `atLimit` means the read and settable checks succeeded and the target equals the current value at 0 or 1. Volume: a target above 0 unmutes, and 0 mutes. `.toggleMute` flips mute and confirms it by reading it back. A pending target is used only when its `kind` and `targetID` match.
