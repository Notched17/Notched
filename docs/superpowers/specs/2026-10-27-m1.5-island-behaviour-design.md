# Notched M1.5: rename + iPhone-style island behaviour (design)

## Context

M1 shipped a single-activity island. Its `ActivityCoordinator` fills the leading and trailing compact slots from *different* activities. It has no minimal bubbles, no alert expansion, no hide/swap/stale/Recent lifecycle, and modules hand it free-form `AnyView`s (ISLAND-BEHAVIOR.md §8). M2 media has to build on the right model, so this session:

- **A.** Renames the app to **Notched**.
- **B.** Rebuilds activities and the island to match the iPhone Dynamic Island (spec §1–§6).

## Part B: design

### B.1 New types (`Sources/Core/Activities/`)

```swift
/// Ranking class, lowest first (spec §2).
enum ActivityKind: Int, Comparable, CaseIterable, Sendable { case passive, media, live, system }

/// Lifecycle. Hidden is a separate user flag (see "Spec changes").
enum ActivityState: Equatable, Sendable { case active, stale, ended(dismissAt: Date) }

enum DismissalPolicy: Equatable, Sendable {
    case `default`          // Recent for the user's retention (15 min default)
    case immediate          // no Recent entry
    case after(Date)        // capped at 4 h
}

struct AlertRequest: Equatable, Sendable {
    var duration: Duration? = nil   // nil → the user's setting (default 4 s)
    var sound: String? = nil        // NSSound name, e.g. "Glass"
}

@MainActor struct LiveActivity: Identifiable {
    let id: ActivityID
    let moduleID: ModuleID
    var kind: ActivityKind
    var relevance: Double = 0
    var isHideable = true
    var staleDate: Date? = nil
    var keylineTint: Color? = nil
    var accessibilityLabel: String              // combined leading + trailing meaning, updated per post
    var openAction: (@MainActor () -> Void)? = nil   // nil → click expands this activity
    var presentation: ActivityPresentation
}

/// What the coordinator knows about a posted activity.
@MainActor struct ActivityRecord: Identifiable {
    var activity: LiveActivity
    let sequence: Int          // start order, the final tiebreak
    var state: ActivityState
    var isHidden: Bool
    var revision: Int          // bumps per update; drives content transitions
    var id: ActivityID { activity.id }
}
```

**`ActivityPresentation`** (`ActivityPresentation.swift`) replaces `ActivityContent`:

```swift
@MainActor struct IslandRegion {            // one named region's view
    init<V: View>(@ViewBuilder _ view: @escaping () -> V)
}

@MainActor struct ExpandedRegion {
    enum Placement: Sendable { case besideHousing, belowIfTooWide }   // belowIfTooWide: leading only
    var priority: Double = 0                 // the highest priority renders full width
    var placement: Placement = .besideHousing
    init<V: View>(priority:placement:@ViewBuilder _ view:)
}

@MainActor struct ActivityPresentation {
    var compactLeading: IslandRegion
    var compactTrailing: IslandRegion?       // nil → the trailing side hides itself
    var minimal: IslandRegion                // live data, fits a 28 pt circle
    var expanded: ExpandedPresentation
}

@MainActor struct ExpandedPresentation {
    var leading, trailing, center, bottom: ExpandedRegion?
}

/// Environment the island gives region views (iOS-style):
/// \.islandActivityState (.active/.stale) · \.islandCompactWidthLimited · \.islandMode (.compact/.minimal/.expanded)
```

Widths are **measured**, not declared. Region views render `fixedSize`, `onGeometryChange` reports their widths to the view model, and the island clamps them (compact ≤ 64 pt per side, minimal 28–45 pt).

**`TransientBanner`** (`TransientBanner.swift`):

```swift
@MainActor struct TransientBanner: Identifiable {
    let id: String                 // same id → replaces and restarts (repeated volume presses)
    let moduleID: ModuleID
    var leading: IslandRegion
    var trailing: IslandRegion?
    var duration: Duration? = nil  // nil → the user's setting (default 2 s)
    var accessibilityLabel: String
    /// Convenience for the common shape: symbol + title leading, value (+ symbol) trailing.
    static func status(id:moduleID:symbol:tint:title:value:valueSymbol:) -> TransientBanner
}
```

### B.2 Coordinator API (rewritten `ActivityCoordinator.swift`)

It stays pure, `@MainActor @Observable`, clock-injected, with `scheduleWake(Date?)` and no polling. Every deadline goes through one `nextDeadline`: alert end, banner end, `staleDate`, Recent `dismissAt` and banner drop.

```swift
@MainActor @Observable final class ActivityCoordinator {
    struct Configuration: Equatable, Sendable {
        var alertExpansionEnabled = true
        var alertDuration: Duration = .seconds(4)
        var bannerDuration: Duration = .seconds(2)
        var recentRetention: Duration = .seconds(15 * 60)   // clamped ≤ 4 h
        static let maxVisible = 3
    }
    struct ActiveAlert: Equatable { let activityID: ActivityID; let endsAt: Date; let serial: Int }

    var configuration: Configuration
    init(configuration: Configuration = .init(), now: @escaping () -> Date = Date.init,
         scheduleWake: @escaping @MainActor (Date?) -> Void = { _ in })

    // Read model
    private(set) var live: [ActivityRecord]        // not ended, ranked, user swap applied (hidden included)
    var visible: [ActivityRecord] { get }          // live minus hidden
    private(set) var primary: ActivityRecord?
    private(set) var minimal: [ActivityRecord]     // ≤ 2, in order [trailing, leading]
    var listedOnly: [ActivityRecord] { get }       // visible beyond 3
    var hidden: [ActivityRecord] { get }
    private(set) var recent: [ActivityRecord]      // ended, newest first, until dismissAt
    private(set) var alert: ActiveAlert?           // the alert expansion on screen
    private(set) var banner: TransientBanner?      // the banner on screen
    private(set) var bounceSerial: Int             // banners, and alerts when expansion is off
    var nextDeadline: Date? { get }

    // Modules (via ActivitySink, still scoped to one module id)
    func post(_ activity: LiveActivity, alert: AlertRequest? = nil)
    func end(_ id: ActivityID, dismissal: DismissalPolicy = .default)
    func endAll(from module: ModuleID)             // module disabled → immediate, no Recent
    func show(_ banner: TransientBanner)

    // User (island gestures, menus)
    func makePrimary(_ id: ActivityID)             // sticky swap
    func cyclePrimary(forward: Bool)
    func hide(_ id: ActivityID)                    // ignored if !isHideable
    func unhide(_ id: ActivityID)
    func dismissRecent(_ id: ActivityID)

    // Island state
    var isInteracting: Bool { get set }            // pointer on / user-expanded island → alerts and banners wait
    func userTookOverAlert()                       // pointer entered during an alert → it becomes a hover expansion
    func advance(to date: Date)                    // replaces expire(at:)
}
```

**Rules, each pinned by a test.** Every test name below is a Swift Testing `@Test` in the rewritten `Tests/ActivityCoordinatorTests.swift`.

| Rule | Scenario tests |
|---|---|
| **Ranking:** class first, then relevance, then start order | `system beats live beats media beats passive`; `higher relevance wins within a class`; `equal relevance → the one started first wins (newcomers don't steal)`; `an update in place keeps its start order` |
| **Primary** | `one activity → it is primary, no minimal`; `two → primary + 1 minimal (trailing), primary chosen by class→relevance→start`; `three → primary + trailing + leading minimal` |
| **Cap of 3** | `four → 3 visible, the 4th only in listedOnly`; `when a visible one ends, the listed one moves up` |
| **Swap** | `makePrimary promotes a minimal`; `the swap is sticky across updates and a newer live activity`; `the swap clears when either swapped activity ends`; `the swap clears when a new system activity arrives`; `cyclePrimary walks visible activities and wraps` |
| **Hide** | `hide removes it from the island but keeps it in hidden and updating`; `a non-hideable activity ignores hide`; `unhide restores it at its rank`; `hiding the primary promotes the next` |
| **Stale** | `past staleDate → state .stale, a wake is scheduled at staleDate`; `an update with a later staleDate → active again` |
| **Ended / Recent** | `end → off the island immediately, in recent until now+retention`; `.immediate → never in recent`; `.after(date) capped at 4 h`; `advance past dismissAt drops it from recent`; `endAll(from:) leaves other modules alone` |
| **Alert expansion** | `post with alert → becomes the active alert for its duration, then nil (the island returns)`; `a new system activity alerts by default`; `two alerts at once → shown one after the other`; `re-alerting a queued activity replaces its entry`; `while interacting the queue waits and the duration starts on release`; `userTookOverAlert ends the alert without collapsing`; `alert of an ended activity is dropped`; `alert expansion off → bounceSerial bumps instead` |
| **Banners** | `show → banner on screen for bannerDuration, then nil (restores multi)`; `same id re-shown extends it`; `a banner during an alert waits; newest pending wins`; `a banner waiting > 5 s is dropped`; `banners bump bounceSerial; they never take a minimal slot` |
| **Deadlines** | `nextDeadline is the earliest of alert/banner/stale/dismiss and is reported to scheduleWake` |

### B.3 Presentation template + expanded `Layout`

`ExpandedRegionsLayout: Layout` (`Sources/Core/Island/Views/ExpandedRegionsLayout.swift`). Its maths is a pure `ExpandedRegionsGeometry.place(…)` with unit tests. It follows spec §4, which is Apple's algorithm.

1. **Center first.** `minSide` = the larger minimum width of leading and trailing. The center is sized with proposal `W − 2·minSide − 2·gap` and placed below the housing row.
2. **Leading and trailing share the rest equally.** Each gets `(W − centerW − 2·gap)/2`, capped beside the housing at `(W − housingW)/2 − inset`. They are top-aligned in the housing row and continue below it next to the center.
3. **Priority.** The region with the highest `priority` takes the full width W in its own row.
4. **`.belowIfTooWide`.** A leading region whose ideal width is more than its share starts below the housing row.
5. **Bottom.** It spans full width below everything. Total height = the lowest bottom, clamped to the 84–160 pt content band (taller content is truncated).

Tests (`ExpandedRegionsGeometryTests`): center sized first; equal sides; priority goes full width; `belowIfTooWide` drops leading; bottom spans the width; height clamps at 160.

**The island owns animation (spec §5).** Every region view goes through `IslandRegionHost`:
- `.transaction { $0.animation = nil }` strips module animations.
- `.animation(Motion.content, value: record.revision)` applies the island's own.
- `.contentTransition(.numericText())` is the default for text, plus symbol effects.
- Swaps use `.id(activityID)` with `.blurReplace`.
- Every duration is ≤ 2 s.
- Stale content dims to 0.55 opacity, and the expanded view shows a quiet "Updating…" caption.

### B.4 Compact rendering + width budget

`CompactLayout` (`Sources/Core/Island/CompactLayout.swift`) is a pure struct with tests. It turns the notch geometry, mode and measured widths into the primary rect, up to two bubble rects, and the hit regions.

- **One activity owns both sides.** Each side's width = max(leading, trailing) + padding, capped at 64 pt, so the widths are balanced. The content hugs the notch.
- **An empty trailing side hides itself.** That side's width is 0, which makes the island asymmetric. This needs a new `NotchGeometry.compactRect(leading:trailing:)` that isn't centred.
- **Width budget.** The total extent from the leftmost bubble to the rightmost is at most notch + 2 × 90 (spec). The primary's sides shrink until it fits. With two or more visible activities, `\.islandCompactWidthLimited = true` (iPhone 18 Pro rule), so modules render reduced content.
- Tests (`CompactLayoutTests`):
  - one activity balanced
  - empty trailing hides
  - 64 pt cap
  - 2 → trailing bubble at a 6 pt gap
  - 3 → leading bubble too
  - budget respected with the widest content
  - side-by-side splits the two activities either side of the notch
  - pill geometry

### B.5 Minimal bubbles: one panel, extra sensors

**Drawing.** Bubbles are drawn as **separate shapes inside the existing island panel**. That panel is already fixed-size and wider than notch + 180 (ADR-0002), so `panelFrame` just unions in the bubble rects. Drawing in one SwiftUI tree is what makes "budding off" possible: shared coordinates, one spring, `matchedGeometryEffect`. Extra *drawing* panels couldn't morph across window boundaries.

- **Notch (black).**
  - A black circle or oval (diameter ≈ the notch height, tuned by eye so it floats in the menu-bar row).
  - It buds off with a spring: it starts at the island's edge at scale 0.6 and travels out to its slot at a 6 pt gap. Merging plays the same motion in reverse.
  - **Goo bridge:** a short spike using a `Canvas` metaball (`alphaThreshold` + `blur`), drawn **only during the bud/merge animation** and swapped for plain shapes at rest, so it costs zero when idle. It ships only if it looks native. Otherwise it's plain spring scale, and I'll tell you.
- **Pill (glass).** Bubbles live in the pill's `GlassEffectContainer` with `glassEffectID`. That's Apple's native glass morph, so they bud off and merge for free.
- **Keyline.** A 1 px stroke of `keylineTint`, or white at 0.3 opacity. It shows on bubbles and the expanded island when the system appearance is dark and the setting is on. It never shows on the attached compact island or the idle notch, because it would outline the hardware.
- **Click-through.** One `IslandSensorPanel` per hit region: the primary island plus each bubble, sized from `CompactLayout`. The 6 pt gaps and everything around the island stay click-through. The top-edge watcher checks every region. `IslandSensorPanel` gains `.rightClicked` and `.scrolled(ScrollSample)` events, each tagged with its region.
- **Side-by-side (iPhone 18 Pro).** The primary's two regions sit together left of the notch and the second activity's two regions sit right of it, all reduced width (`limited = true`) inside one continuous shape. A third activity becomes a trailing bubble.

### B.6 Expanded pages, alerts, banners, interaction

- **Pages:** `[visible activities in rank order…, Home]`, with a subtle dot indicator below the bottom region. It appears only when there's more than one page.
  - Hovering the primary or a bubble opens *that* activity's page. Hovering with nothing live opens Home.
  - A two-finger horizontal swipe in the expanded view pages, with `.alignment` haptic at the threshold.
- **Home:** the M1 header (clock left of the housing, glass Settings/Pause right of it) above an **activity list** with three sections: Live, Hidden (tap to unhide) and Recent ("Ended 3 min ago", clear button). With nothing live it shows the current empty state.
- **Alert expansion:** the island morphs to that activity's page (expand spring → hold → collapse spring) and returns to the previous presentation. While the pointer is on any island, `isInteracting = true` and alerts queue. The bounce stays for banners only.
- **Banners:** a wide compact shape. Bubbles merge back into the island for the banner and bud off again afterwards (your decision).
- **`HoverStateMachine` additions (tested):**
  - `.alertBegan` / `.alertEnded` events. A pointer entering during an alert turns it into a hover expansion.
  - `.clicked(region)`: with "Click to open" it gives `.performOpenAction` or `.makePrimary`; with "Click to expand" it expands that activity.
- **`SwipeRecognizer` (pure, tested):** accumulates scroll deltas per gesture phase into `.cycleNext`, `.cyclePrevious` or `.hide` (swipe up). It handles natural-scrolling inversion and fires once per gesture.
  - On the compact island: horizontal cycles the primary, and up hides.
  - Right-click opens a context menu: Hide, Make Primary, Show All Activities.
- **Esc:** after a click inside the expanded island, the panel becomes key (a non-activating panel, so your app stays active) and Esc collapses it. On collapse it gives up key status. Hover never takes focus.

## Your decisions (answered 27 Oct)

- **Expanded width** = notch width + 2 × 140 pt (488 on this Mac). It's scaled by the existing Expanded size slider, and pill displays use 408. Height follows content: the notch row + 84–160 pt. `IslandMetrics.expandedBase` becomes this derived size, and the panel stays fixed at the maximum, so the morph never resizes a window.
- **Esc:** the island takes keyboard focus only after a click inside the expanded island. Then Esc collapses it and focus goes back. Hover never takes focus.
- **Banners with bubbles:** the bubbles merge into the island, the banner uses the full width budget, then the bubbles bud off again.
- **Leaked test plists:** delete `~/Library/Preferences/me.rkck.DynamicNotch.tests.*.plist` (only those), and fix the test so it cleans up.

## Spec changes I'm proposing (tell me if you disagree)

1. **`hidden` is a separate user flag, not a lifecycle state.** A hidden activity can still go stale or end, and then it should move to Recent.
2. **`alert` is a `post(_:alert:)` parameter, not a stored field.** It's one-shot, and a stored field would re-fire on every re-post of the same struct.
3. **With two or more visible activities, `compactWidthLimited` is always on.** That matches the iPhone 18 Pro rule and is deterministic. Measuring first and then shrinking would make widths oscillate.
4. **New `system` activities alert by default** (spec §1, "a new high-priority activity").
5. **Banners wait while the island is expanded** and are dropped after 5 s. The spec doesn't say what happens to them.
6. **An alert on a hidden activity still expands, but leaves the activity hidden.**
